# C–D 用户研究材料（冻结前草案）

本文件不构成伦理批准或知情同意。`open-decisions.md` 第 9 项已接受恢复成功/时间、感知控制、Raw NASA-TLX 与 UMUX-Lite 的推荐组合；量表原文、计分代码、样本量和停止规则仍须在 6–8 人 pilot 与伦理确认后冻结，不能据此直接开始正式招募。

## 条件与顺序

- 条件代码 `X/Y` 对参与者和现场主持人隐藏；私有映射在分析冻结后解盲为 C/D。
- 两个任务实例难度配对，采用 `XY/YX` 两序列；奇偶 participant ID 不能直接决定序列，使用预生成随机表。
- 每个条件先连续修改，再出现一个从冻结错误池抽取的受控错误；实例不跨条件复用。
- 主持人口播、提示时点、最长任务时间和求助规则逐字一致。

## 背景问卷（最小化）

1. 年龄区间（不收精确生日）；
2. 使用生成式 AI 的频率（从不 / 每月 / 每周 / 每天）；
3. 使用旅行规划工具的频率；
4. 自评技术熟悉度（1–5）；
5. 是否需要无障碍安排（可跳过，仅用于现场支持，不进入方法效果分析）。

不收姓名、真实旅行计划、支付信息、API Key 或账号密码。联系方式与 participant ID 分库存放。

## 每条件行为任务

主持人只读目标卡，不解释系统机制：

1. 建立一个预算/锁或偏好；
2. 完成 3–5 个局部修改与一个无关干扰编辑；
3. 检查最终行程是否仍符合早期目标；
4. 遇到受控错误后自行发现并恢复；
5. 确认最终状态或明确放弃。

记录：完成与否、开始/结束时间、自然语言轮次、点击、候选切换、Diff 展开、接受/拒绝、撤销、版本恢复、求助、重复表述、错误发现时点、残留错误。所有事件使用单调时钟；视频时间只作仲裁，不替代事件日志。

## 每条件即时问卷

### 感知控制（已选为主要主观终点，待 pilot 冻结计分）

1–5（完全不同意—完全同意）：

1. 我能预测这次操作会修改哪些部分。
2. 系统保留了我先前仍然有效的要求。
3. 我能判断当前界面为什么变成这样。
4. 出现意外变化时，我知道如何恢复。

反向题单列报告，不在看到数据后决定是否进入合成分：

5. 我不得不重复已经说明过的要求。

### 工作负荷

采用 Raw NASA-TLX 六维原始评分：Mental、Physical、Temporal、Performance、Effort、Frustration，不增加参与者自定义维度权重。题目原文与计分代码仍须在 pilot 后按哈希冻结。

### 可用性

采用 UMUX-Lite 两题及原始 7 点量表，不改写题意、不与自定义感知控制题混算。SUS 不再属于当前预注册方案；若在 pilot 后更换，必须在查看 C–D 方向前记录理由并重新冻结材料。

### 候选与适当依赖

1. 候选之间存在实质差异（1–5）；
2. 我对最终选择有信心（1–5）；
3. 对预注册的正确/错误候选分别记录接受或拒绝，不直接询问“你是否信任系统”。

## 结束访谈

- 哪一次变化最出乎意料？你如何发现？
- 锁、候选、Diff 和版本历史分别帮助或妨碍了什么？
- 你何时愿意直接接受，何时会检查或拒绝？
- 如果只能保留一个机制，会选哪个，为什么？

访谈编码本与量化假设分开；主题在至少两名研究者独立开放编码小样本后冻结，不能只摘录支持 H1–H4 的引文。
