# 盲法语义与候选标注手册（草案）

状态：冻结前试标版本。标注界面不得显示 A–D 方法名、系统分数、文件名或候选策略名。

## 标注单位

每个单位包含：任务说明、截至当前轮仍有效的目标、明确退出的旧目标、该轮用户请求、必要的初始/当前状态，以及匿名化输出。语义轮与候选批次分成不同单位，候选标注者看不到系统最终选中项。标注包不显示方法、模型、run ID、候选策略、规则分或系统排名；结构 ID 使用每样本 HMAC 假名，地点目录 ID 保留以核对事实。

正式人工单位只覆盖 combined/probe，以及确实由模型执行的 setup；distractor 不送人工语义标注，其路径、行为信封、约束和 ID 保持由确定性代码评分，并在最终数据中标记 `assessment=structural_proxy`。论文必须分别报告盲法人工语义完成与该结构代理，不能把二者合并后统称为人工正确率。

## 语义目标评分

对每个目标分别标注：

- `2 = 完全满足`：结果满足目标，且没有需要用户修正的遗漏；
- `1 = 部分满足`：方向正确但存在实质遗漏或含糊；
- `0 = 未满足/相反`；
- `NA = 证据不足`：给定材料无法判断，不得猜测。

二元主分析仅将 2 计为满足；0/1 合并为未完全满足。0–2 有序结果作为敏感性分析。

## 旧目标泄漏

仅评价任务账本中已明确被替换或退出作用域的目标：

- `leaked=true`：旧目标仍改变了当前输出、拒绝或解释；
- `leaked=false`：输出依据当前目标，旧目标未产生可观察影响；
- `NA`：当前轮没有机会检验该旧目标。

“结果碰巧与旧目标一致”但没有冲突或代价时不自动判泄漏；必须有可观察影响或反事实 rubric。

## 冲突与拒答

先依据隐藏真值标记该请求是否应澄清/拒绝，再标注系统行为：正确接受、正确拒绝、错误接受、错误拒绝。解释只有在指出真实冲突且没有虚构事实时才算正确。

## 候选相关性（用于 NDCG@3）

每个候选独立给出 0–3：

- 3：完整满足当前目标，保持全部有效目标，变化成本合理；
- 2：目标基本满足，存在轻微但可接受的遗漏；
- 1：部分有用，但需要明显修复；
- 0：无效、越权、违反约束或与请求无关。

随后在同一批合格候选中选出人工最佳项；并列允许。Top-1 regret 使用预先固定的效用映射计算，不能根据系统排名修改标签。

## 标注流程与一致性

1. 先用不进入正式数据的 20 个单位培训与修订手册；
2. 冻结手册后随机抽取至少 20% 正式单位双标，并分别保证语义样本和候选批次各至少 20%；
3. 标注者独立完成后才计算一致性；
4. κ/α 低于预先门槛时，报告问题、修订手册并重新标注受影响批次，不能只删除分歧样本；
5. 仲裁者只处理分歧，不覆盖一致标签；保存原始标签与仲裁标签。

机器记录中 `role=annotator` 表示独立标注，`role=adjudicator` 表示仲裁。正式合并要求所有非空标签附证据；独立标注缺失或不一致时必须存在唯一仲裁值，脚本不会多数投票或默认补 0/2。

冻结门槛：二元完整目标 Cohen's κ ≥ 0.70；目标 0–2 与候选相关性 0–3 的 Krippendorff ordinal α ≥ 0.67。总样本、语义样本和候选批次分别至少 20% 双标，且目标和候选各至少 20 个可比较的双标值（存在候选样本时）；不能把全部复核集中在一种样本上。

## 数据最小化

不向标注者展示 API Key、用户身份、精确个人行程或自由文本中的个人信息。正式导出使用随机 sample ID，方法映射表单独保存并在分析冻结后解盲。
