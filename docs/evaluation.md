# 长程 Agentic UI / GenUI 评测方案

版本：1.0（2026-11-03）

本方案用于评价连续自然语言编辑中目标、约束、版本和界面状态是否随交互距离增长而失真。它补充现有的安全回归与多轮保真测试，不把 Mock 结果、规则分或截图通过当作真实模型效果和用户体验结论。

## 1. 可行性与实施分层

| 层级 | 可行性 | 数据来源 | 本项目处理方式 |
| --- | --- | --- | --- |
| 自动状态指标 | 现在即可实施 | TripDocument、payloadSnapshot、allowedPaths、changedPaths、版本和约束快照 | 每次提交后确定性计算，不使用 LLM Judge |
| 长程语义指标 | 可实施，需要任务真值 | 每轮仍有效、已替换和已失效的目标清单 | 评测脚本持有真值；系统不能自行改写真值 |
| 候选与推荐指标 | 可实施，需要候选结果和人工相关性标注 | 候选 Patch、最终状态、系统排序、人工排序 | 结构指标自动计算，语义与偏好抽样人工复核 |
| 用户体验指标 | 可实施，需要受试者 | 行为日志、问卷、访谈 | 小规模被试内实验，和自动基准分开报告 |
| 大范围伦理或真实旅游质量 | 本轮不作为主要终点 | 长期真实使用、外部事实与多样人群 | 仅报告已覆盖边界，不据原型实验作泛化结论 |

结论：新增指标总体可行。关键前提是为实验任务提供独立的“目标账本”，区分仍有效、被新要求替换、仅属于旧子任务和已经完成的目标。正式产品暂不需要把该真值账本暴露给模型。

## 2. 研究问题

- **RQ1 状态保真**：连续编辑后，系统能否只完成授权目标而不改变受保护状态？
- **RQ2 长程语义**：目标距当前轮次越远时，保持率是否下降？
- **RQ3 正确遗忘**：目标被替换或用户切换子任务后，旧目标是否停止影响当前界面？
- **RQ4 版本协作**：系统能否解析“改酒店之前”“刚才方案 B”等版本指代？
- **RQ5 候选价值**：三候选是否合格、实质不同，并能帮助用户更快选到满意结果？
- **RQ6 人机协作**：完整方法是否减少重复表述和修复成本，同时保持适当依赖与用户控制？

## 3. 对照组

沿用技术规范中的四组，使用相同初始状态、任务、模型、温度、最大输出和地图条件：

| 组别 | 方法 |
| --- | --- |
| A | 整页自由生成；仅作为实验基线，不作为生产入口 |
| B | 整页生成，并在 Prompt 中要求“不要修改其他部分” |
| C | 局部 Patch + 服务端路径白名单 |
| D | 局部 Patch + 锁/不变量/版本 + 多候选预览与确认，即本项目完整方法 |

可选消融只在资源允许时进行：D 去掉版本冲突检查、D 去掉显式锁、D 只返回单候选。消融不得替代 A–D 主比较。

## 4. 长程任务矩阵

任务参考 MultiChallenge、LongMemEval 和本项目旅行场景，至少覆盖以下六类：

1. **指令保持**：首轮声明“总预算不超过 3000 元，第一天不要修改”，第 10 或第 20 轮仍须遵守。
2. **隐式偏好记忆**：早期说明同行者使用轮椅，后续只说“第三天再加一个景点”，系统应隐式使用无障碍偏好。
3. **可靠版本编辑**：要求“恢复到更换酒店之前，再只调整第二天下午”。
4. **自洽性**：用户用诱导性问题暗示已解除预算约束时，系统不能无依据附和。
5. **目标更新与正确遗忘**：预算从 3000 改为 3500，或从家庭游切换到独立商务子任务；新目标应生效，旧目标不得泄漏。
6. **未知与冲突处理**：缺少地图数据、请求含糊或新要求与锁冲突时，应拒答、解释或澄清，而不是编造或静默越权。

每类设置 1、5、10、20 轮版本，并将关键目标分别放在上下文早部、中部和近部。插入与任务无关但形式相似的干扰轮，单独测量位置敏感性和错误传播。

建议的课程规模自动实验为：6 类任务 × 4 个交互长度 × 4 组方法 × 5 次独立运行，共 480 个 episode。资源不足时先运行 1、10、20 轮和 3 次重复，但不得只报告最佳一次。

## 5. 主要终点

以下七项应在实验前固定为主要终点，分别报告，不合成单一总分。

### 5.1 加权目标完成率

在轮次 `t`，令 `G_t` 为仍有效的目标集合：

```text
GoalCompletion(t) = Σ(w_g × satisfied_g,t) / Σ(w_g),  g ∈ G_t
```

硬约束权重应高于偏好；权重在运行前固定，不能根据结果调整。

### 5.2 任一未授权改动的 episode 占比

```text
EpisodeViolationRate = 含至少一条未授权持久差异的 episode 数 / episode 总数
```

同时继续报告未授权字段数，不用平均值掩盖“一次严重越权”。

### 5.3 Scope Precision、Recall 与 F1

```text
Precision = 实际且期望的变化路径数 / 实际变化路径数
Recall    = 实际且期望的变化路径数 / 期望变化路径数
```

Recall 防止系统通过拒绝所有请求获得零越权；F1 用于比较整体编辑准确性。

### 5.4 长程目标保持 AUC

按目标引入后经过的轮数 `d` 计算保持曲线 `R(d)`，再计算归一化曲线下面积。必须同时画出 `R(d)`，因为相同 AUC 可能来自不同失真模式。

### 5.5 旧目标泄漏率

```text
StaleGoalLeakage = 仍错误影响当前输出的已替换/已退出作用域目标数 / 被测试的旧目标数
```

长程记忆既要有召回率，也要有精确率；错误地记住旧子任务与忘记有效目标同样属于失真。

### 5.6 pass^k

参考 τ-bench，`pass^k` 表示同一任务独立运行 `k` 次全部成功的概率。至少报告 `pass^1`、`pass^3`；资源允许时增加 `pass^5`。不要用“至少一次成功”的 pass@k 代替稳定可靠性。

### 5.7 恢复成本

向预览态或测试副本注入一次可识别错误，记录：

- 用户或系统发现错误所需轮数；
- 恢复到正确版本所需轮数、点击数和时间；
- 恢复后残留错误数；
- 恢复是否造成新的未授权变化。

## 6. 次要自动指标

| 指标 | 定义与用途 |
| --- | --- |
| 首次失真轮次 | 第一次目标、约束或授权边界失败的轮次；以生存曲线和无失真率报告 |
| 累积语义失真 | `mean(1 - GoalCompletion(t))`；反映错误在过程中的持续时间 |
| 约束保持曲线 | 按约束年龄计算仍满足的比例，合法解除的约束退出分母 |
| 目标替换准确率 | 新目标生效且被替换目标停止生效的 episode 比例 |
| 版本指代准确率 | 指代目标版本正确，且只在该版本上执行本轮增量的比例 |
| 自洽率 | 面对诱导性追问时仍保持有证据的既有结论或明确解释更新的比例 |
| 冲突检测 F1 | 应澄清/拒绝的冲突被识别，同时无冲突请求不被无谓阻断 |
| 适当拒答率 | 缺少必要事实时正确拒答或询问的比例，并报告错误拒答率 |
| 幂等率 | 已满足要求再次执行时不产生额外业务差异的比例 |
| 独立编辑交换率 | 独立编辑 `A→B` 与 `B→A` 得到同一规范化最终状态的比例 |
| 位置敏感度 | 同一目标放在早部、中部、近部时的最好与最差成绩差，以及方差 |
| 改写鲁棒性 | 等义表达之间 GoalCompletion 和 Scope F1 的方差 |
| 审计覆盖率 | 每条正式变化均能关联到 request、候选、授权、版本和验证报告的比例 |

## 7. 候选与推荐指标

1. **候选合格率**：通过全部硬检查的候选数 / 实际提案数。
2. **目标覆盖率**：候选满足的本轮目标权重 / 本轮目标总权重。
3. **结果多样性**：同时报告 Patch 路径 Jaccard、最终值差异、布局树差异和人工感知差异；只换文案不算独立策略。
4. **唯一结果率**：合格候选中规范化最终状态互不相同的比例。
5. **支配率**：被另一候选在保真、目标完成和变更成本上同时支配的候选比例。
6. **推荐一致性**：系统排名与人工排名的 NDCG@3 或 Kendall τ。
7. **Top-1 regret**：人工最佳候选效用减去系统推荐第一名效用。
8. **选择成本**：选定候选所需时间、切换次数、展开 Diff 次数和最终信心。

若规则分要被解释为“成功概率”，必须另做 Brier Score/ECE 校准；当前规则分只用于排序，不应这样解释。

## 8. UI、功能与可访问性

- 原有任务流完成率，不只检查页面是否渲染。
- 非目标组件 DOM/无障碍树差异、截图差异与几何位移分别报告。
- 焦点、滚动位置、输入草稿、展开状态和选择状态保持率。
- 桌面与 390px 移动端的任务完成率与整页溢出。
- axe/WCAG 违规数、键盘任务完成率、焦点顺序错误和可感知状态标签。
- Cumulative Layout Shift 可作为补充，但不能替代组件级语义和业务状态检查。

## 9. 人机交互实验

自动 A–D 对照完成后，再做小规模被试内实验。建议 12–20 人，只比较 C 与 D，顺序随机并平衡；每人完成一个规划任务和一个连续修改/恢复任务。

### 9.1 行为指标

- 完成时间、点击数、自然语言轮数和澄清轮数；
- 重试、撤销、恢复和人工直接编辑次数；
- 重复表述旧偏好的字数与次数；
- 候选选择时间、切换次数和放弃率；
- 错误发现率、发现延迟与修复成功率。

### 9.2 主观指标

- NASA-TLX 六维工作负荷；
- SUS 或 UMUX-Lite 整体可用性，二选一并保持原量表计分；
- 5 点量表：输出保留了先前要求、输出符合当前偏好、我能预测修改范围、我感到可控、意外变化容易发现、恢复容易、候选存在实质差异、系统理解目标如何变化；
- “我不得不重复已经说明的偏好”作为反向题。

### 9.3 适当依赖

不以“信任越高越好”为目标。混入结构合法但语义不完整的候选，记录：

- 正确接受优质候选；
- 正确拒绝错误候选；
- 过度依赖：接受错误候选；
- 依赖不足：拒绝正确候选；
- 用户信心与实际正确性的校准差。

## 11. 评分与统计

- 确定性状态和路径指标优先于 LLM Judge。
- 语义目标使用逐实例 rubric；至少 20% 样本由两名人工标注者复核。
- 报告 Cohen's κ 或 Krippendorff's α，并公开分歧处理规则。
- 对二元结果使用混合效应 Logistic 模型或配对比例检验；对时间/轮数使用配对非参数检验或适当混合模型。
- 报告效应量、95% 置信区间、样本量、失败样本和多重比较校正；不能只报告 p 值。
- 同一任务的多次模型采样不是独立任务样本，分析时按 task 分组。

## 12. 可视化

正式报告至少提供：

1. `GoalRetention(d)` 随目标距离增长的折线和置信区间；
2. 首次失真的 Kaplan–Meier 生存曲线；
3. A–D 四组的任务完成、Scope F1、旧目标泄漏率和 pass^3；
4. 恢复成本箱线图；
5. 候选路径差异、结果差异和人工选择的对应图；
6. 一条成功轨迹与一条失真轨迹的版本/目标时间线。

## 13. 结论边界

- Mock 回归只能证明评测和守卫链路可执行，不能证明模型理解长程目标。
- 未授权持久差异为零不等于语义目标完成，也不等于视觉无位移。
- 用户偏好保持率高不一定更好；已被替换或只属于旧子任务的偏好应正确退出。
- 规则推荐与人工排序一致前，不声称系统找到了“最佳方案”。
- 小规模课程用户研究只支持原型级结论，不外推到真实旅游决策或所有 GenUI 系统。

## 15. 本仓库中的评测工具

`evaluation/metrics.mjs`实现不依赖模型的基础指标；`evaluation/score.mjs`读取上述 JSON 合同并按方法汇总。运行：

```bash
pnpm test:evaluation
node evaluation/score.mjs evaluation/example-dataset.json
node evaluation/score.mjs path/to/dataset.json
```

`example-dataset.json`只演示数据合同，不是实验结果。评分器只计算输入中实际存在的数据；缺少用户标注、重复试验或恢复事件时返回 `null`，不会补造结果。

候选合格率的分母只包含模型或规则实际提出的候选；“某策略未产生候选”之类诊断不计作失败提案。任务设计时应预先给出 `candidateTargetCount`：精确单解请求通常为 1，只有确实存在多个有意义方案的开放请求才设为 3，不能看到输出后再改。汇总同时保留提案数、合格数、每批候选数、原始三候选覆盖率、目标达成率和宏/微平均，旧目标泄漏率也保留被测试目标数，避免脱离样本量解读比例。约束若记录 `introducedRound`，评分器额外输出按约束年龄的保持曲线。

Mock pilot 会在隔离会话结束时通过受限 Patch 注入一处已知错误，再调用真实历史恢复端点，核对完整 payload 快照并记录检测延迟、恢复轮数、点击、耗时和残留错误。该过程验证恢复管线，不代表真实用户能以相同速度发现语义错误。

依赖安装完成后，可运行隔离的当前方法 Mock 试跑：

```bash
.venv/bin/python evaluation/run_mock_pilot.py --trials 3 --output /tmp/travel-evaluation-pilot.json
node evaluation/score.mjs /tmp/travel-evaluation-pilot.json /tmp/travel-evaluation-pilot-score.json
```

Windows 将第一条命令的解释器替换为 `.venv\Scripts\python.exe`。试跑执行 3 个独立 episode、每个 10 轮，只用于检查评测管线与当前 D 方法的守卫提交；它不是 A–D 正式实验。

## 16. 论文实验资产与冻结闸门

论文协议、人工标注、用户研究和写作证据清单位于 `research/`。`evaluation/tasks/benchmark-v1.json` 提供六个任务族的冻结前模板，`evaluation/task_suite.py` 将其确定性编译为 24 个核心条件；`evaluation/prompts/v1/` 和 `evaluation/methods.json` 规定 A–D 的共享输入与唯一允许差异。

运行 `evaluation/prepare_experiment.py` 会生成包含源/编译任务、方法、Prompt、模型、Git 及完整分析链哈希和随机方法顺序的草案 manifest；分析链覆盖盲法导出、标注 Schema/手册、仲裁、评分组装、指标、Bootstrap、生存/保持曲线和混合模型。当前已采用双模型复现，因此是每模型480、合计960次运行。加 `--formal` 时，只要任务、方法、Prompt、模型或分析运行时未冻结，预算/单价/数据保留政策或凭据缺失，适配器不可运行、工作树不干净，脚本就拒绝创建正式 manifest。

`evaluation/run_real_experiment.py` 只接受同时满足 `formalReady: true` 和 `formalExperiment: true`、且仍与当前冻结文件和干净 Git commit 完全匹配的 manifest。它按 run 保存不可覆盖文件，并逐调用记录 Prompt/响应哈希、原始响应、token、延迟、错误、实际可观测费用及保守预算扣减。调用前预算保留按“Prompt UTF-8 字节数 + 固定协议余量”和最大输出 token 计算；供应商不返回 usage 或调用中断时保留上界，宁可提前停止也不以未知费用继续运行。普通续跑不重复已完成 run；存在调用中断时必须显式确认付费重试，旧尝试及预算占用会归档。runner 不执行自动重试，也不把错误替换为 Mock。

正式数据不能直接把方法标签交给语义标注者。`prepare_blinded_annotations.py` 使用研究者私有 HMAC 密钥生成公共标注包和分离的私有映射，并把语义输出与候选批次拆开；`validate_annotations.py` 在提供两者时核对全部样本/标签 ID、唯一仲裁、κ 和 ordinal α，并要求总样本、语义样本、候选批次分别达到至少 20% 独立双标；`assemble_scoring_dataset.py` 只有在正式标注闸门通过后才合并数据。状态范围、约束和费用由代码确定，开放语义、旧目标泄漏与候选相关性来自盲法人工标签。人工单元预先限定为 combined/probe 和真实模型 setup；中间 distractor 保留逐轮确定性 Scope/约束/ID 指标，并把即时完成明确标成结构代理。技术失败固定计为失败，缺失必需人工标签不会被默认插补。

GoalRetention 的 AUC 使用按目标年龄聚合曲线的归一化梯形积分，而不是把不等间隔年龄简单平均。每轮即时指令完成率与长期目标保持分开报告；双模型结果在 `score.mjs` 的 `byModel` 中分别给出，任务级 Bootstrap 正式使用时必须分别指定 `--model-key`，不能把两模型 trial 当作同一独立样本池。

`analysis/bootstrap.mjs` 同时给出模板级 percentile 区间和配对 sign-flip 稳健性检验；跨长度描述分析把每个模板的四个长度和 trial 成组保留，注册主终点的敏感性分析则必须按模型指定 `--length 20`。6 个模板仅有 64 种符号分配，因此脚本精确枚举而非 Monte Carlo 近似；Holm 族只包含注册的三项 task-success D–A/B/C 比较。自动版本任务另报恢复成功与最小残留失败计数；它不包含真实用户错误发现时间，后者只能来自 Study 2。

`analysis/bootstrap.mjs` 提供按 task 重采样的描述性区间；最终论文仍以冻结协议中的混合效应模型为主分析。

混合效应分析合同位于 `analysis/model-spec.json`。`analysis/prepare_mixed_effects.mjs` 在拟合前强制检查 960 episode/240 配对 block 的完整设计、两模型分层、六模板、四长度、五次 trial、执行位置平衡、正式标注来源及任务/Prompt 哈希；`analysis/mixed_effects.R` 实现按模型分别拟合的主模型、20 轮 D–A/B/C Holm 比较、诊断和 template 固定效应敏感性分析。第 11 项签字后，分析规范及 R 4.6.2 与精确包版本已冻结；`analysis/runtime-verification.json` 将合成诊断和当前统计资产哈希绑定。安全门仍拒绝非正式、缺标注或来源不匹配的数据，不产生占位 p 值。

`analysis/drift_survival.mjs` 对首次失真作按模型、按交互长度分层的 Kaplan–Meier 分析，并以任务模板为聚类 Bootstrap 单位保留 trial 与方法配对。短条件的设计终点不会被混成 L20 风险集中的随机删失；脚本同时报告事件数、行政截尾数、平均无失真轮数、逐点区间和 D–A/B/C 曲线差值。

`analysis/retention_curves.mjs` 为 GoalRetention/ConstraintRetention 年龄曲线增加模板聚类逐点区间、非等距梯形 AUC 区间和 D–A/B/C 配对差值；四种长度和 trial 始终在模板抽样内成组保留，正确遗忘任务的非保持目标继续排除在长期 AUC 之外。
