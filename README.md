# 旅序 · AI 旅行规划工作台

旅序将行程规划、局部修改、方案比较和历史恢复放在一个工作台中。填写城市、出行天数与预算后生成行程，再用自然语言调整选中的日期、时段或景点。每次修改先预览、再确认，便于保留满意的安排。

## 主要功能

- **按需求规划**：设置城市、出发日期、1–14天行程、同行人数、总预算及旅行偏好。
- **局部编辑**：选择一天、一个时段或一张景点卡片，修改描述、开始时间，或从真实地点目录中更换景点。
- **方案比较**：对比最小改动、效率优先、体验优先三种策略，查看实际卡片预览、字段差异和推荐依据。
- **锁定保护**：锁定不希望改动的日期、时段和卡片，修改只在允许范围内进行。
- **交通与地图**：查询景点间交通路线，展示地图，并提供景点和酒店备选。
- **保存与恢复**：行程自动保存在服务端，可查看版本差异、撤销操作或恢复历史快照。
- **灵活浏览**：支持卡片与时间轴、预算明细、行程导出，以及桌面双栏和手机布局。

## 快速开始

### 环境要求

- Python 3.12
- Node.js 24
- pnpm 11.25.0

下载本仓库并解压，或使用Git克隆。在包含 `package.json` 和 `backend/` 的项目根目录打开终端。以下命令均相对于项目根目录，不需要修改为某台电脑的固定路径。

### Windows 安装与启动

在PowerShell中执行：

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r backend/requirements.txt
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

完成安装后，双击 [启动旅序.cmd](启动旅序.cmd)。脚本会构建网页、检查服务版本并打开浏览器。停止服务时双击 [停止网页.cmd](停止网页.cmd)。

也可手动启动：

```powershell
pnpm build
.\.venv\Scripts\python.exe -m uvicorn backend.app:app --host 127.0.0.1 --port 8011
```

打开 **[http://127.0.0.1:8011/](http://127.0.0.1:8011/)**。

### macOS / Linux 手动启动

```bash
python3.12 -m venv .venv
.venv/bin/python -m pip install -r backend/requirements.txt
npm install --global pnpm@11.25.0
pnpm install --frozen-lockfile
[ -f .env ] || cp .env.example .env
pnpm build
.venv/bin/python -m uvicorn backend.app:app --host 127.0.0.1 --port 8011
```

首次创建 `.env` 后按下节配置服务。已有配置时请保留原文件。

## 选择使用方式

| 使用方式 | 所需配置 | 适合场景 |
| --- | --- | --- |
| 无密钥体验 | 无需模型或地图Key | 首页点击“打开三日演示（不调用模型）”，体验内置杭州行程、规则候选及保存恢复 |
| AI行程与修改 | 模型服务地址、模型ID、API Key | 规划行程，使用LLM理解自然语言并生成修改方案 |
| 完整地点与路线 | 在模型配置之外填写高德Web服务Key | 查询其他城市的真实地点、交通路线与静态地图 |

未配置地图服务时可使用内置杭州地点目录，页面会说明路线尚未连接。其他城市的地点查询需要可用的地图服务。

## 模型与地图配置

编辑项目根目录的 `.env`。配置示例见 [.env.example](.env.example)，支持DeepSeek及其他兼容OpenAI Chat Completions格式的模型服务。

```dotenv
# 行程规划使用真实模型
AGENT_MODE=llm

# 候选修改默认使用真实模型；无需模型时可设为mock
CANDIDATE_AGENT_MODE=llm

LLM_BASE_URL=https://api.deepseek.com
LLM_MODEL=填写服务商实际支持的模型ID
LLM_MODEL_LABEL=填写页面显示的模型名称
LLM_API_KEY=填写自己的模型API密钥

# 高德地图Web服务Key
AMAP_KEY=填写自己的高德Web服务密钥
```

使用其他兼容服务时，将 `LLM_BASE_URL`、`LLM_MODEL` 和 `LLM_API_KEY` 换为对应配置。Base URL填写服务的基础地址，不要再附加 `/chat/completions`。修改配置后重新启动服务。

| 配置项 | 说明 |
| --- | --- |
| `AGENT_MODE` | 行程规划模式：`llm`为真实模型，`demo`为规则演示 |
| `CANDIDATE_AGENT_MODE` | 候选修改的默认模式：`llm`或`mock`，也可在网页中切换 |
| `LLM_BASE_URL` | 兼容模型服务的基础地址 |
| `LLM_MODEL` | 账号实际可用的模型调用ID |
| `LLM_MODEL_LABEL` | 页面中的模型显示名称 |
| `LLM_API_KEY` | 服务端模型密钥，也支持使用 `DEEPSEEK_API_KEY` |
| `LLM_TIMEOUT` | 单次模型请求超时秒数，默认70 |
| `LLM_MAX_TOKENS` | 模型输出上限，默认6000 |
| `AMAP_KEY` | 高德地图“Web服务”Key，用于地点、路线及静态地图 |
| `CANDIDATE_TTL_SECONDS` | 候选有效期，默认600秒，可设为30–3600秒 |
| `AGENT_REQUESTS_PER_MINUTE` | 每分钟生成和路线等请求上限，默认12 |
| `ALLOWED_ORIGINS` | 允许的网页来源，多个地址用逗号分隔；同源访问可留空 |
| `COOKIE_SECURE` | 本地HTTP使用 `false`，公开HTTPS服务使用 `true` |

`.env`仅由服务端读取。请勿提交真实密钥、个人行程数据库或运行日志到GitHub；仓库提供的 `.gitignore` 已包含这些本地文件的排除规则。

## 使用指南

### 规划行程

首页填写城市、出发日期、出行天数、同行人数、全程总预算和偏好，然后开始规划。已有行程时，也可以选择“继续上次行程”。

预算指全部同行人的全程总预算。门票、住宿和交通费用为估算，实际价格、开放时间与可订情况以对应服务为准。

### 修改局部安排

1. 开启编辑模式，选中目标日期、时段或景点卡片。
2. 如需保护其他内容，先锁定相应组件。
3. 在“告诉我你的想法”中输入需求，并勾选本次允许修改的字段。
4. 生成候选，比较预览、具体差异和推荐依据。
5. 点击“采用此方案”保存，或取消本次候选。

可尝试：

- 选择一个时段，输入“安排轻松一些”。
- 选择一张景点卡片，输入“将开始时间改为14:00”。
- 勾选“真实景点”，输入“换成室内景点，保留时间和其他内容”。

开始时间可以跨时段调整，但需保持当天时间顺序，且目标时段不能已锁定。更换景点只使用当前行程的真实地点目录；没有合适备选时会明确提示。

**Mock是规则模式，LLM是真实模型模式。** Mock支持有限的节奏、时点和地点替换规则；LLM模式需要有效的服务配置。系统不会将模型调用失败伪装成Mock成功。

三个策略最多提供三个经过校验且不同的候选。选区过小、字段限制、锁定或备选不足时，可能少于三个。规则推荐分用于辅助比较，不代表真实交通效率或完整旅行体验的保证。

### 地图、展示与预算

使用行程中的“添加交通与地图”或“刷新交通与地图”查询路线。更换地点或时间后，可重新查询受影响日期的路线。

卡片样式和时间轴可通过展示按钮调整；修改整天共享样式时需选择对应日期。全局预算明细与预算硬上限使用独立确认入口。预算硬上限限制可填写的预算值，不等同于控制实际消费。

### 历史与恢复

点击“操作记录”，查看版本列表和字段差异。恢复旧快照会同步恢复当时的行程、展示、组件锁及约束，并创建一个新版本；原历史保留。恢复前请阅读确认说明。

未采用的候选只作为临时预览，服务重启或候选过期后需要重新生成。另一窗口修改行程后，旧候选会提示版本冲突，重新获取当前状态再生成即可。

## 数据保存

本地运行时，行程和版本记录保存在：

```text
backend/.runtime/travel.sqlite3
```

关闭网页或重启服务不会清空已保存行程。使用同一浏览器访问，可以继续上次行程；当前通过访客Cookie区分使用者，尚未提供账号登录、跨设备同步或多人共同编辑同一行程。

清理Cookie、换浏览器或换设备后，不会自动找回原行程。备份本地数据时，先停止服务，再保存数据库所在目录。Docker部署的数据保存在独立的数据卷中。

## 部署

本项目同时需要前端和Python后台，上传GitHub源码不会自动生成可用网站，也不能仅依靠GitHub Pages运行完整功能。

仓库提供 [Dockerfile](Dockerfile) 和 [compose.yaml](compose.yaml)。在部署机器准备 `.env` 后运行：

```bash
docker compose up --build -d
```

默认将服务映射到部署机器的 `127.0.0.1:8011`，数据保存在 `travel-data` 卷。公开访问时，通过反向代理提供HTTPS，并配置自己的 `COOKIE_SECURE` 和 `ALLOWED_ORIGINS`。反向代理应允许SSE流式响应，避免缓存或缓冲生成进度。

保持单个应用worker；临时候选和并发控制使用进程内存，多实例部署需要共享存储支持。

## 常见问题

**模型显示已配置，为什么仍然失败？**  
配置状态只说明填写了必要信息。请检查模型ID、API地址、账号余额与权限，并查看页面返回的错误提示。

**为什么不能修改某个区域？**  
确认已开启编辑模式、选中包含活动的组件，并检查当前组件、上级日期或目标时段是否锁定。更换地点还需授权“真实景点”字段。

**为什么没有生成三个候选？**  
只有满足范围、锁定和时间等约束且内容不同的候选才会显示。明确指定单个时间、备用景点不足或选区限制，都可能减少候选数量。

**上传GitHub后，别人能直接打开我的本地地址吗？**  
不能。`127.0.0.1`指访问者自己的电脑；其他使用者需要自行安装运行，或访问你部署的公开服务地址。

**是否支持订票和酒店预订？**  
目前提供规划、地点选择和费用估算，尚未接入实时房态、订票、预订或支付。
